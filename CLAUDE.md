# CLAUDE.md: hamzatariq.site

Portfolio and inbound lead site for Hamza Tariq (freelance developer: React/Next.js websites, dashboards, AI chatbots). The full roadmap is in `PLAN.md`; the current state is in `AUDIT.md`.

## Working rules

- Work phase by phase in this order: 0 → 1 → 2 → 4 → 3 → 7 → 5 → 6 → 8. Never start the next phase until the owner says "approved".
- Before a phase, list the env variables, API keys and accounts it needs.
- At the end of a phase: run `npm run build`, run mobile Lighthouse on new pages, and report what changed and what the owner must provide.
- Never feature the owner's own site anywhere in the UI: not as a project, case study, card, image, cover, figure, hero demo, stat or headline, and no post about migrating or rebuilding it (owner, repeated; 2026-11-09). A blog post may mention it in at most one line of body text. Same rule in `content/STYLE.md` and `docs/AUTOPILOT.md`.
- Never invent clients, numbers, results, testimonials or quotes. If a fact is missing, write a visible `TODO(owner)` in the page and add it to `OWNER_TODO.md`.
- Real facts come only from `content/owner/` (once it exists) and from the owner's messages.

## Stack

- **Framework:** Next.js 15 App Router, React 19, TypeScript (strict). All pages are statically generated unless they need request data.
- **Home page** (`/`, `src/app/page.tsx`) is a normal server-rendered page in `SiteShell` (sections in `src/components/home/`, styles `Home.css`): full-screen hero (live aurora behind it and the header, "Available for new projects" badge, location line, giant headline "I build [Word Rotate: websites / dashboards / AI chatbots] that bring businesses customers." whose lines fly in from the sides, then headshot + lead on the left and Shimmer Book a free call + Free SEO audit + CV link on the right, "Scroll" cue), the scroll-velocity band (`VelocityBand`), client wordmarks (Magic UI Marquee), intro statement + Number Ticker stats, services (stacking cards, `ServiceStack` + `ui/StackFx`, shared with /services: on desktop each card pins under the header and the next slides over it while the covered one shrinks and dims), selected work (Dulhahouse, Nagina, AuraLuxe, Trekkerz as 3D cards in a pinned horizontal scroll on desktop, `HorizontalWork`), reviews (`HomeReviews`, heading "What clients say": never a brand count in that heading or the wordmark label (owner, 2026-11-12); Text Reveal featured quote, not pinned, + Infinite Moving Cards), how I work (Timeline + photo), free tools, latest posts, then the shell's "Let's work together" marquee + Background Beams CTA. Every route uses `next/link`.
- **Hero aurora** (`src/components/home/Aurora.tsx`): layered silk waves in the accent colours from one fragment shader on a plain WebGL canvas (no three.js; the package was removed). Both shaders run through `src/lib/shaderCanvas.ts`, which compiles with `KHR_parallel_shader_compile` (a blocking compile cost ~800 ms of main-thread time on Windows) and asks for `failIfMajorPerformanceCaveat` (no software-rendered WebGL). The CSS gradient on `.hero-bg` is the server-rendered look; the canvas fades in after `load` + idle, on phones too, but never with reduced motion, without WebGL or on low-power devices (under 4 cores / 4 GB where reported). DPR capped at 1.5 (1 on phones); drawing stops off-screen or in hidden tabs. The hero title animation is transform-only on purpose: a blur filter there repaints every frame and moves LCP to the end of the animation.
- **One navbar everywhere:** `SiteHeader` (`src/components/site/SiteHeader.tsx`, styles `SiteHeader.css`): the logo (`Logo.tsx`: an "H." mark (H + full stop, 2026-11-13) on an accent-gradient tile + "Hamza *Tariq*"; the favicon `src/app/icon.tsx` repeats the mark), Services dropdown, Work, About, Blog, Free SEO Audit (badge) in a glass capsule with one highlight pill that slides to the hovered/active link, and a "Let's talk" gradient pill with an arrow (`BookCall`: Calendly or /contact). Contact and Hire me are in the mobile menu and the footer. Full menu from 1280px, burger below. Aceternity Floating Navbar behaviour: frosted pill once scrolled, hides on scroll down, returns on scroll up; every menu route is prefetched when the browser is idle. Links always open real pages (never `#anchors`); active state comes from the pathname (nested pages included).
- **Preloader** (`src/components/site/Preloader.tsx`, styles in `Theme.css`): the logo tile scales in, the H draws stroke by stroke, the name wipes in, the dot pops, then the curtain slides up (about 1.9 s; no progress bar) and the home hero lines fly in after it. Pure CSS, once per browser session (`PRELOADER_SCRIPT` in <head> sets `pre-skip`), off for reduced motion; the page underneath is already rendered.
- **Other routes** use the server component `SiteShell` (`src/components/site/SiteShell.tsx`) for header, footer and CTA.
- **Fonts:** Bricolage Grotesque (display headings, `--font-display` → `--font-head`), Geist (text, `--font-text` → `--font-sans`, Latin subset from `@fontsource-variable/geist`) and Instrument Serif italic (accent words, `--font-accent` → `--font-serif`). All SIL OFL, self-hosted from npm packages via `next/font/local` in `src/app/layout.tsx`; never `next/font/google`, so builds work without network access. `display: "swap"`, never `"optional"` (Chrome then skips the fonts on a first visit and the site renders in Arial). Fallbacks are our own size-matched `@font-face` rules at the top of `system.css` ("Geist/Bricolage/Instrument Serif Fallback", one face per weight range, measured on the site's text), with `adjustFontFallback: false`: next/font's own fallbacks were too wide and caused a 0.11 layout shift when the fonts swapped in. No `experimental.inlineCss`: it put the CSS into the HTML twice (style tag + RSC payload) and into every prefetch. Not Satoshi/General Sans: the Fontshare licence forbids keeping font files in a public repository (and subsetting); switching needs a private repo.
- **Images:** `next/image` everywhere. Remote hosts are allow-listed in `next.config.ts`.
- **Site facts** (URL, email, social links, agency) live in `src/lib/site.ts`. Do not hard-code them elsewhere.
- **Backend:** Supabase only, for all dynamic data: Postgres (`leads`, `chat_sessions`, `chat_messages`, `events`), `pgvector` (`site_chunks`), Auth (owner-only `/admin`), Storage. Do not add any other database or auth provider.
  - Every schema change is a migration in `supabase/migrations/` with RLS enabled on every table. Apply with `npx supabase db push --linked` (the CLI is logged in to the owner's hamzabuildsweb account; project ref `nuewfjfpdlujusoebklf`). Do not use the Supabase MCP tool for this project: it is connected to a different account.
  - Regenerate TypeScript types after each migration: `npx supabase gen types typescript --linked --schema public > src/lib/supabase/database.types.ts`.
  - Public writes go through `SECURITY DEFINER` functions (`app_*`) that check `SUPABASE_SERVER_SECRET`; the owner reads through Auth + RLS. Server code uses `rpcClient()` / `getOwner()` from `src/lib/supabase/server.ts`.
- **AI assistant ("Ask Hamza's AI", Phase 4):** widget on every page except `/admin`, loaded when the browser is idle (`AssistantLoader` in the root layout). `/api/chat` embeds the question with Gemini, fetches matching `site_chunks`, and streams a Gemini reply grounded only in that content; chats are logged to Supabase. Model and why: `src/lib/assistant/gemini.ts`.
  - Gemini free tier, no billing (owner's decision). One chat model, no Flash-Lite fallback. No chat rate limits (the lead form keeps its 5/hour per IP limit). When Gemini fails, is out of quota (then skipped at once until it resets) or doesn't start replying within 7 s, the reply comes from the offline answer bank `content/chatbot/answers.json` via `src/lib/assistant/offline.ts` (keyword/phrase/typo matching, no API call); no match → "Hamza will answer this personally" + lead form, WhatsApp and email. Off-topic questions (coding help, trivia, jokes, homework) get exactly one line: "I can only help with questions about Hamza's services and projects." Answers in the bank use only owner facts; keep them in sync when prices or services change.
  - `site_chunks` is filled by `scripts/embed-content.mjs` from the built HTML plus `content/owner/`. It runs as `postbuild` on production deploys only (failures never block a deploy) and locally with `npm run embed` after `npm run build`.

## Design conventions

- **Design system** (About, /services and service pages; reuse it for new pages): `src/components/site/ds/` (`Section` label→heading→lead rhythm, `Icon`, `CountUp`, `Reveal` scroll fade-in via `data-reveal`, `Mockups` laptop/phone/browser frames around real screenshots, `HeroVisual` per service, `Faq` accordion, `OpenChat` opens the AI assistant) with styles in `src/components/styles/Premium.css` (`x-` classes). Real screenshots and real numbers only; hidden elements must not widen the page at 390px.
- `BookCall` is the only "Book a free call" button: Calendly popup when `CALENDLY_URL` is set, otherwise `/contact`. `SiteShell` takes `cta` (closing band text) and `stickyCta` (mobile bar on service pages).

- Dark "Nebula" theme (owner, 2026-11-12; tokens in `src/styles/system.css`; never hard-code colours): ground `--bg` #06050f, glass cards `--bg-elev`, ink `--fg` #f4f2ff (`--ink-rgb` for hairlines/tints at an alpha), muted text `--muted`, hairlines `--line`/`--line-strong`. Accent family: violet `--accent` #6d4aff (fills; white text on it), light text/link shade `--accent-hi` #b9abff, blue `--accent-2`, cyan `--accent-3`; `--accent-grad` paints accent words and thin lines, `--accent-fill` paints primary buttons. State colours `--ok`, `--warn`, `--bad`. `Theme.css` holds the theme layer (ambient background, accent words, glass cards with pointer glow, buttons); it loads before page-level CSS, so its overrides are prefixed with `.page` / `.site-header`.
- Type: Bricolage Grotesque display at weight 600 with tight tracking (`--fs-display`, `--fs-h1`, `--fs-h2`, `--tracking-display`), Geist for text; headings scale with viewport width and height. Accent words in headings are a direct `<span>`: Instrument Serif italic painted with `--accent-grad` (gradient text is used for these accent words only).
