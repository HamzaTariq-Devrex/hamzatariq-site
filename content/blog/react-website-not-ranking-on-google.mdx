If your React website is not ranking on Google, the most common reason is simple: the page Google downloads is almost empty. A standard React app (built with Vite or Create React App) sends one blank HTML shell for every URL and builds the content in the browser with JavaScript. Google has to run that JavaScript before it can see anything, and many crawlers never do.

The good news is that this is a technical problem, not a content or design problem. You can usually keep your React components and your design, and fix how the pages are delivered. I did exactly that on my own site, and the mobile SEO score went from 83 to 100.

Below I explain why it happens, how to check your own site in a few minutes, and what to fix first.

## Why a React website is not ranking on Google

Most React sites are single-page apps (SPAs). When someone opens any URL, the server returns the same small HTML file. It has an empty `<div id="root">` and a script tag. Everything you see on screen is created later by JavaScript.

For people with a fast phone this works fine. For search engines it creates three problems:

1. **Empty HTML.** The first thing a crawler receives has no headings, no text and no links. Google puts JavaScript pages in a render queue and comes back later to run them. That second step can be slow, and if anything fails (a script error, a blocked API call, a timeout) Google indexes the empty version.
2. **One title for every page.** The `<title>` and meta description live in `index.html`, so every URL shares them. Google sees ten pages with the same title and no description, and has no idea which page answers which search.
3. **Missing basics.** SPAs often ship without a sitemap, a robots.txt file, canonical URLs or structured data, because the framework doesn't create them for you.

Google explains its own process in its guide to [JavaScript SEO basics](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics). The short version: crawl, then render, then index. Every step you make Google do in the browser is a step that can go wrong.

Other crawlers are less patient. Link previews on WhatsApp, LinkedIn and Slack read only the raw HTML. So do many AI search tools. If the HTML is empty, your site shows up with no title, no image and no text.

## How to check your site in five minutes

You don't need any paid tool for this. Try these checks on your home page and one inner page.

### View the page source

Open your site, right-click and choose **View page source** (not Inspect). Search for a sentence that you can see on the page. If it's not in the source, the content is created by JavaScript and crawlers that skip JavaScript can't see it.

### Compare titles

Open three different pages and look at the browser tab. If they all show the same title, Google sees the same title too. Each page needs its own title and its own description.

### Check robots.txt and sitemap.xml

Add `/robots.txt` and `/sitemap.xml` to your domain. If either one returns your home page, a blank page or an error, search engines are missing the map of your site.

## The fixes that matter most

Here is the order I work in. The first two make the biggest difference.

### 1. Send real HTML for every URL

This is the main fix. Each URL should return HTML that already contains its headings, text, links and images. There are two ways to get there:

- **Server-side rendering (SSR):** the server builds the HTML when someone asks for the page.
- **Static generation:** the HTML for each page is built once at deploy time and served from a CDN. This is the fastest option and works for most business sites.

[Next.js](https://nextjs.org/docs) gives you both and still uses React components, so your existing code moves over with small changes. That's why I recommend it for React sites that need search traffic.

### 2. Give every page its own title and description

Every page needs a unique title (short enough to show fully in search results) and a meta description of about 150–160 characters that says what the reader gets. In Next.js you export `metadata` from each page, and it lands in the server HTML, not after JavaScript runs.

### 3. Add the files search engines look for

- **sitemap.xml** with every page you want indexed.
- **robots.txt** that allows crawling and points to the sitemap.
- **Canonical URLs**, so `www` and non-`www`, or URLs with tracking parameters, don't count as duplicates.

### 4. Add structured data

Structured data (JSON-LD) tells Google what a page is: a person, a business, a service, an article, an FAQ. It can make your result richer and helps Google connect your pages.

### 5. Make the first screen load fast

Speed matters for both people and rankings. Google measures it with Core Web Vitals; the main one is Largest Contentful Paint (LCP), the time until the largest thing on screen appears. On React sites the usual problems are heavy JavaScript, a preloader that hides content, unoptimized images and web fonts loaded late.

## Should you migrate to Next.js or patch your React app?

You have three realistic options. Here is how I explain them to clients.

| Option | What it fixes | Good for |
| --- | --- | --- |
| Patch the SPA (react-helmet, a prerender service) | Some titles, some previews | Small sites that can't change hosting |
| Migrate to Next.js | Real HTML, metadata, sitemap, speed | Sites that need Google traffic or leads |
| Rebuild from scratch | Everything, plus a new design | Sites that need a redesign anyway |

Patching is cheaper at first, but it leaves the empty HTML in place. Prerender services add another moving part that can break quietly. For most business sites the migration is the better deal: your components and design stay, and every page starts working for search.

If you're unsure, start with an audit. You'll know which problems you actually have before you spend money on fixing them.

## A quick checklist before you call anyone

Use this to see how much work your site needs:

- [ ] View source shows your real text, not just an empty root div.
- [ ] Every page has its own title and meta description.
- [ ] `/robots.txt` and `/sitemap.xml` return real files.
- [ ] Every page has a canonical URL.
- [ ] Structured data exists for your business or person.
- [ ] The largest element on mobile appears quickly, with no preloader hiding it.
- [ ] Images use modern formats and have alt text.

If three or more boxes are empty, your React website is probably invisible to most of Google's crawl, no matter how good it looks.
